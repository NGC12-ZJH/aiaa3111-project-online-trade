## 1. 起点：问题从哪里来

### 1.1 原研究问题

先按 RFM 给顾客分群，再在每个群里挖关联规则（L）。在相同规则预算下，看它能否胜过全局规则（G）和同规模的随机分组（R），并在未来时期保持价值。

### 1.2 检查 C 的商品层规则时发现的问题（11-11 至 11-12）

| 现象 | 证据 |
|---|---|
| 强规则几乎都是“同类换款” | 前件和后件属于同一子类的比例：G 81%、C0 93%、C1 76%、C2 75% |
| 商品层看不出分群价值 | C 的随机对照：二商品组间差异 0.2409，只略高于随机最大值 0.2403 |
| 小群几乎没有规则 | C0 只有 46 条合格规则，去掉同类换款后只剩 3 条 |

### 1.3 排除了一个错误的解释

最初猜测是“批发商只买一种商品”。用 Discovery 期 7,521 张订单检查后发现**这个解释不成立**：一张订单通常有十几个不同商品，同款换色只占约 12%，大批量顾客的同款比例反而更低。

**真正的原因**：同款组合非常固定，计数集中，所以容易过门槛；跨品类的搭配虽然普遍，但分散在成千上万个商品对上，每一对都达不到“联合次数 ≥ 20”。**把商品合并成品类之后，这些分散的搭配才可能被看到**。这就是做品类层级的动机。

另外复算了“新商品”比例：Validation 期只有 8.8% 的购买是新商品，原方案引用的 Test 期 30.9% 来自组员文档。所以“新商品”只作为 Test 期的补充分析，不作为主要动机。

## 2. taxonomy_v0（11-12 上午）

### 2.1 做法

| 步骤 | 内容 | 脚本 |
|---|---|---|
| 1 | 建商品目录：4,724 个编码，记录规范描述、全部写法、首次出现时期 | `step1_catalog_cluster.py` |
| 2 | 清洗商品名（去掉颜色、尺寸等词），用 `all-MiniLM-L6-v2` 句子向量编码 | 同上 |
| 3 | 只用 2010-12-01 之前出现的 4,072 个商品做 K-means（K = 120），**只用来看清有哪些商品类型和做兜底** | 同上 |
| 4 | 读完 120 个聚类样例后写 53 条有序关键词规则，**第一条命中的规则生效** | `rules_v0.py`、`step2_tag.py` |
| 5 | 没命中的商品：所在聚类里 ≥ 50% 是同一子类就采用它，否则标 other | `step2_tag.py` |
| 6 | 品类层挖规则：把篮子里的商品换成子类，用和 C 相同的门槛挖 G / L / R | `step3_concept_mining.py` |

### 2.2 结果

- **覆盖**：按 Discovery 购买加权，关键词规则直接命中 93.2%，聚类兜底 3.4%，other 3.4%。
- **一致性**：同一商品不同写法的标签一致 95.6%；同一编码前缀家族一致 91.4%。
- **品类层的分群差异第一次超过全部 20 次随机分组**：
  - 群间 Bray–Curtis 0.108，随机组最大值 0.096；
  - 群与群外的差异 0.090，随机组最大值 0.086；
  - Top-10 组合不重合度 0.405，和随机组最大值持平；
  - 经验 p = 0.048，这是 20 个随机种子能得到的最小值。
- **出现了有业务含义的跨类组合**：暖手宝 → 热水袋（lift 3.5）、钥匙扣 → 钱包（3.5）、蛋糕纸托 → 派对餐具（2.6）。
- **Validation 期探索（预算 50）**：命中率 G 63.2%、L 50.4%、R 中位数 42.0%。L 稳定高于 R，但不如 G。

### 2.3 v0 的局限，也就是做 v1 的理由

1. **没有人工金标准**，准确率未知；
2. **子类过粗**：挂饰占 6.9%、玩具 5.3%、招牌 4.4%，品类层的热门规则因此变成“玩具 ↔ 挂饰”这类大众组合；
3. **规则和类别名都由 AI 起草**，没有经过验证；
4. **规则有系统性错误**，事后发现的例子：名字里有 PARTY 的商品一律归进派对用品，咖啡杯被归成茶壶。

## 3. v1 的方法与参考来源

### 3.1 参考来源

| 来源 | 借鉴了什么 | 我们的做法与发现 |
|---|---|---|
| Gholamian et al. (2024), *LLM-Based Robust Product Classification in Commerce and Compliance*, EMNLP 2024 CustomNLP4U Workshop（arXiv:2408.05874） | ① 商品描述被缩写或截断时，给 LLM **5 个最相似的已标注例子**能大幅提升准确率和稳健性；② **一次性扁平分类**优于“先大类、再小类”的分层分类 | ② 照做：从 76 个子类里一次选一个。① 作为 R1 实现，并用 R2（不给例子）做消融。**我们的结果与该文不同**：R2（90.0%）不低于 R1（87.0%），差异不显著（p = 0.31）。原因是我们的例子池是 v0 规则标签，带有系统性噪声，例子会把错误传给模型。见第 5.4 节 |
| Cohen (1960) 的 κ 系数 | 衡量两位标注人之间的一致性，扣除碰巧一致的部分 | A vs D：κ = 0.923 |
| Wilson (1927) 的置信区间 | n = 200 时准确率的 95% 置信区间 | R2：85–93% |
| McNemar (1947) 的配对检验 | 比较两种方法在同一批商品上的对错 | R1 vs R2：p = 0.31（不显著）；R1 vs v0：p < 10⁻²¹ |
| 预注册（pre-registration）思路 | **先写定选择规则和验收门槛，再看结果** | README 第 6 节的规则（大类 ≥ 90%、子类 ≥ 80%；准确率最高者为主方法），在评测前已写定 |

**说明**：v1 中“由 LLM 提方案、由人做决定”的流程，以及缓存、冻结、泄露检查等做法，是为本项目设计的工程实践，不是照搬某篇论文。

### 3.2 工具选择：为什么用 DeepSeek 官方 API，而不是学校 HPC

| | DeepSeek API（采用） | 学校 HPC + vLLM（放弃） |
|---|---|---|
| 准备时间 | 几分钟 | 要装 vLLM、下载权重，环境情况未知 |
| 模型 | `deepseek-v4-pro`（带思考的推理模型） | A40 上大约只能跑 14B 级别的模型 |
| 复现 | 每次返回都写进缓存，`--offline` 可以不联网重建 | 开源权重更容易复现 |
| 费用 | 全部做完约 3 美元（按未核实的价格） | 每人 50 元 GPU 额度 |

还看过学校 API（`aigc-api.hkust-gz.edu.cn`），需要校园 VPN；以后可以用来做 R4 的“换一家模型”对照。

### 3.3 v1 的核心设计原则

1. **LLM 提建议，人做决定**：每条 LLM 建议都写进 `taxonomy_v1_decisions.json`，由人接受、修改或拒绝，可以追溯。
2. **只用商品文字**：分类时不用销量、共购、顾客、分群或时期信息。
3. **类别结构只由早期商品决定**：只看 2010-12-01 之前出现的商品。
4. **先冻结，再评测**：类别结构冻结后才看金标准结果，看了结果就不能回头改。
5. **评测时不能作弊**：参考例子和类别表里的代表例子都排除金标准商品及其同前缀家族；标注人和裁定人看不到任何机器标签；指南里手写的举例也要逐个检查，不能和金标准商品撞上。
6. **每一步都能复现**：所有 API 返回都有缓存（`llm_cache.jsonl`），关键文件有 SHA-256 指纹。

### 4.2 抽金标准（先于任何评测）

### 4.3 第 1 步：找出要拆分和合并的子类（不用 LLM）

规则是提前写定的：在 Discovery 期购买占比 ≥ 3.5% 或早期商品数 > 150 的要拆；出现在不到 20 个购物篮里的要合并。

结果：7 个子类要拆（挂饰、玩具、招牌、盘碗、小布袋、蜡烛香薰、首饰），`pet_items` 要合并，`other` 要重新归类（`v1_step1_stats.py`）。

### 4.4 第 2 步：LLM 提方案（`v1_step2_propose.py`，约 1.07 美元）

一共 9 个请求：7 个拆分提案、1 个 other 重新归类、1 个设计系列和节日关键词。

过程中遇到并解决的问题：

| 问题 | 解决办法 |
|---|---|
| 推理模型每条要思考约 2 万个 token，按顺序发要将近一小时 | 9 条请求同时发出 |
| 第一版提示词只允许“在子类内部拆”，模型就新建了“装饰杂物”类来装放错的商品 | 改成允许移到已有子类，并明确禁止建杂物类；作废 0.10 美元 |
| 挂饰那条（287 个商品）输出被截断 | 输出上限从 3.2 万调到 6.4 万；作废 0.13 美元 |

### 4.5 人工决定（B，3 轮）

| 轮次 | 决定 |
|---|---|
| 第 1 轮：结构 | 7 个拆分全部接受；合并 16 组过小或重复的子类，92 → 76 个；圣诞树挂饰并回“悬挂装饰”，因为节日由 `season` 属性单独表示；设计系列只保留 22 个有名字的系列；补 10 个圣诞关键词 |
| 第 2 轮：定义 | 修正 22 个子类的定义和边界规则。例如 `furniture_knobs` 原来的定义反而排除了抽屉把手，`cushions_textiles` 排除了带芯靠垫，`greeting_cards` 排除了明信片 |
| 第 3 轮：例子池 | 用 23 条规则纠正 61 个错标种子，例如 10 个咖啡杯被 v0 标成茶壶；CHARLOTTE BAG 留在“时尚手袋” |

### 4.6 第 3 步：生成类别表，然后冻结

- `v1_step3_build.py` 生成：
  - `taxonomy_v1.json`：每个子类有英文名、中文名、定义、边界规则和 3 个代表例子；代表例子来自不同系列，并避开金标准商品；

### 4.7 R1–R3：LLM 给金标准商品打标签（`llm_tag.py`，约 1.72 美元）

| 轮次 | 配置 | 作用 |
|---|---|---|
| R1 | 5 个参考例子 + 主提示词 | 主方法候选（少样本） |
| R2 | 不给例子 | 消融：例子的作用（零样本） |
| R3 | 5 个参考例子 + 换措辞的提示词 | 提示词稳定性 |

- 每个请求约 9,000 个输入 token，**95% 命中 DeepSeek 的前缀缓存**，所以每轮只要约 0.5 美元。
- R1 与 R3 子类一致 98.0%，预先写定的稳定性门槛（≥ 85%）通过；R1 与 R2 一致 86.0%（`compare_runs.py`）。
- 发现的问题：
  - 每轮都有 3–4 个难判断的商品，模型把 4,000 个 token 的输出上限全用在思考上，返回空答案，需要重答；
  - 自报置信度没用：中位数 0.98，没有一条低于 0.7；
  - 服务器断开过一次连接，已补上重试和容错。

- 两项泄露检查：
  - 228 个例子商品，没有一个和金标准同名；

## 5. 得到的结果

### 5.1 准确率

| 方法 | 子类准确率（95% CI） | 大类准确率 | 子类宏平均 F1 | 按购买量加权子类准确率 |
|---|---|---|---|---|
| v0 关键词规则 | 49.0%（42–56%）；只看仍沿用 v0 代码的 121 个商品为 81.0% | 81.5% | 0.411 | 61.1% |
| **R2 LLM 不给例子** | **90.0%（85–93%）** | **92.5%** | **0.880** | **93.1%** |
| R1 LLM + 5 个例子 | 87.0%（82–91%） | 90.5% | 0.823 | 91.4% |
| R3 换措辞 | 87.0% | 90.5% | 0.824 | 91.3% |
| 标注人 A / D（参照，偏高） | 97.5% / 94.5% | 98.0% / 96.0% | — | — |

### 5.2 按预先写定的规则得出的结论

- 候选方法（v0、R2、R1）中子类准确率最高的是 R2，R1 落后 3 个百分点，超出“2 个百分点以内再看加权准确率”的范围 → **主方法为 R2**。
- R2 大类 92.5% ≥ 90%、子类 90.0% ≥ 80% → **达到冻结门槛**。

### 5.3 错误分布

- 两人都确定的 146 个商品，R2 准确率 98.6%；有人不确定的 54 个商品只有 66.7%。**机器的错误集中在人也觉得难的商品上**。
- 错误集中在本来就模糊的边界：悬挂装饰 vs 桌面装饰、彩旗花环 vs 悬挂装饰、毛毡娃娃 vs 缝纫套件、派对蜡烛。
- LLM 会把看不懂的商品标成 other（水平仪、熨衣板套、浴室秤），而人从不用 other。

### 5.4 参考例子为什么没有帮上忙

- R1 错、R2 对的 15 个商品里，有 14 个是 R1 的错误答案正好出现在参考例子中。原因是例子池里还有 v0 留下的错标（例如名字含 PARTY 的商品都在派对用品里），以及外观相近但类型不同的商品。
- 正确子类出现在例子里时（占 87.5% 的商品），R1 准确率 92%；正确子类不在例子里的 25 个商品，R1 只有 52%。
- **结论**：少样本提示的效果取决于例子池的质量。例子池本身有噪声时，给例子不一定比不给好。这一点和 Gholamian et al. (2024) 的结论不同，可以写进报告的讨论部分。

## 6. 已知局限（报告里需要如实说明）

1. **样本量**：金标准只有 200 个，准确率的置信区间宽约 ±4–5 个百分点。
2. **信息不对称**：中文指南根据合并决定补了几处具体商品（例如饮用玻璃杯归杯子、丝带归礼品包装），人看到了，而冻结的英文定义里没有、LLM 看不到。这对 LLM 是偏严格的。
3. **标注独立性**：需要确认 A、D 是否独立完成、有没有借助 AI 工具，尤其是 DeepSeek。
4. **系列判断的缺陷**：用“编码前 5 位相同”判断同一系列，漏掉了连号系列（例如 TOAST ITS 是 21354–21358）。这只影响 R1、R3 的参考例子，不影响主方法 R2。
5. **例子池仍有噪声**：3,702 个种子只纠正了按“类型词”扫描出来的错标。
6. **模型不可完全复现**：temperature 设为 0 也不保证每次输出完全一样，模型本身也可能更新。所以结果以缓存为准，复现时用 `--offline`。
7. **价格未核实**：费用按第三方网站的价格计算。
8. **v0 的品类层结论仍有局限**：随机对照只匹配了人数，没有匹配活跃度；只有 20 个随机种子。这些在 v1 上同样需要处理（见下一节）。
