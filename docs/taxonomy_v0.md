# 商品品类层级 taxonomy_v0：步骤、探索结果与基线定位

> 负责人：B（Jinghan ZHAO）· 分支：`b/taxonomy` · 日期：2026-11-12
> 状态：**探索性基线，尚未人工验收，不是冻结版本。** 本文所有数字只用 Profile、Discovery、Validation 三个时期；没有读取 Test 期数据。

## 0. 一句话总结

C 的商品层规则约八成是“同类商品换款”（例如粉色午餐包 → 红色午餐包），信息量很低，分群差异也和随机分组差不多。v0 用**关键词规则 + 文本聚类**给全部 4,724 个商品打上 53 个子类标签，然后把购物篮换成“品类”重新挖规则。结果显示：**在品类层，三个真实顾客群之间的差异超过了全部 20 次随机分组**，在 Validation 期的规则命中率也稳定高于随机分组。v0 透明、可复现、不需要 GPU，因此作为后续 LLM 标注和人工复核的基线。

## 1. 为什么要做商品品类层级

### 1.1 C 的商品层结果遇到的问题

C 在 Discovery 期用 FP-Growth 挖了全局（G）、三个真实群（L）和 20 套随机分组（R）的规则（见 `c/pattern-mining` 分支的 `docs/c_pattern_mining_progress.md`）。我们检查这些规则后发现：

| 现象 | 证据 |
|---|---|
| 强规则几乎都是同类换款 | 预算 50 选中的规则 100% 前后件名称共享关键词；全部合格规则中，用 v0 子类判断仍有 75%–93% 属于同一子类（见第 5.1 节） |
| 分群差异不比随机明显 | C 的随机对照：二商品组间差异 0.2409，只略高于随机最大值 0.2403；三商品组间差异只超过 5/20 次随机分组 |
| 小群几乎没有规则 | C0 只有 46 条合格规则，去掉同类换款后为 0 条 |

### 1.2 是不是因为批发商只买一种商品？——不是

Online Retail II 的顾客中有不少批发商，我们最初猜测“同类换款规则多是因为批发进货习惯”。用 Discovery 期 7,521 张订单检查后，**这个解释不成立**（`explore_baskets.py`）：

| 顾客类型（按每行购买数量中位数） | 订单数 | 每单商品数中位数 | 每单“系列”数中位数（严格口径） | 有同款搭档的商品比例（严格口径） |
|---|---|---|---|---|
| 大批量（≥ 12 件/行） | 3,205 | 10 | 9 | 11.4% |
| 中间 | 3,139 | 17 | 16 | 13.7% |
| 小批量（≤ 2 件/行） | 1,177 | 27 | 25 | 12.5% |

- 一张订单通常有十几个**不同**的商品；同款换色只占约 12%。
- 大批量顾客反而订单更小、同款搭配略少。

**真正的原因**：同款组合非常固定，计数集中，联合次数和 lift 都高（lift 中位数 9–12），所以排在规则榜前面；而跨品类的搭配虽然普遍，但分散在成千上万对商品上，每一对都过不了“联合次数 ≥ 20”的门槛。**把商品合并成品类后，这些分散的搭配才可能被看见**——这就是做品类层级的动机。

### 1.3 为什么不把“新商品”作为主要动机

原方向 1 方案以“Test 期 30.9% 的购买是新商品”为主要动机。我们在 Validation 期复算（`explore_validation_novelty.csv`）：

| 指标 | Validation 期 |
|---|---|
| Discovery 未见过的商品占购买记录比例 | 8.8% |
| 含至少一个未见商品的篮子 | 42.3% |
| 篮子里全部是未见商品 | 2.6% |
| 按 5 位编码前缀合并后的未见比例 | 8.7% |

新商品问题主要出现在 Test 期，Validation 期并不严重。因此“把新商品接回旧规则”只作为 Test 期的补充分析；**品类层级的主要用途是区分“同类换款”和“跨类搭配”，并在品类粒度上比较分群。**

## 2. 输入数据与防泄漏设计

| 输入 | 来源（固定提交） | 用途 |
|---|---|---|
| `clean_transactions.csv.gz` | A 快照 `2ae672b` | 商品描述、首次出现时间、Discovery 购买次数 |
| `baskets_long.csv.gz` | A 快照 `2ae672b` | Discovery / Validation 购物篮 |
| `customer_clusters.csv`、`random_groups.csv` | B 快照 `2ae672b` | 真实分群和 20 套随机分组（种子 42–61） |
| `rule_evidence.csv.gz`、`product_names.csv` | C 分支 `fb734c4` | C 的商品层合格规则，用于复查 |

`prepare_inputs.py` 用 `git show <提交>:<路径>` 把这些文件取到本地的 `data/processed/local/b_taxonomy_inputs/`（被 `.gitignore` 忽略，不会上传）。

防泄漏原则：

1. **只用商品文字给商品分类**，不用销量、共购、顾客、分群或时期信息。Discovery 购买次数只用于给人工复核排序。
2. **类别结构只由早期商品决定**：文本聚类只用 2010-12-01 之前出现过的 4,072 个商品；之后才出现的商品只是被分配到最近的已有类别。
3. **规范描述只用首次出现时期的写法**：同一编码有多种写法时，取它首次出现那个时期里最常见的写法，避免用到后期的销量信息。
4. **不读 Test 期**。品类层规则的检查只用 Discovery（挖掘）和 Validation（探索性检查）。

## 3. v0 的构建步骤（通俗版）

### 第 1 步：建立商品目录（`step1_catalog_cluster.py`）

- 4,724 个有效商品编码，每个编码一行。
- 记录：规范描述、全部写法（596 个编码有多种写法）、首次出现时期、是否属于“定结构用的早期商品”。
- 首次出现时期分布：Profile 3,670 个、Discovery 402 个、Validation 219 个、Test 432 个、范围外 1 个。

### 第 2 步：清洗文字并做文本向量

- 去掉颜色、花纹、尺寸等不影响“是什么东西”的词（RED、SPOTTY、RETROSPOT、LARGE、SET OF……），让相似度更多反映商品类型。
- 用句子向量模型 `sentence-transformers/all-MiniLM-L6-v2`（固定版本 `1110a243`）把每个描述变成向量。这是**文本模型**，不是用购买记录训练的商品向量，因此不会把共购信息带进分类。

### 第 3 步：文本聚类，只用于“看清有哪些类型”

- 对 4,072 个早期商品做 K-means，K = 120，随机种子 42。
- 之后出现的商品分配给最相似的聚类中心。
- 每个聚类列出 7 个最常买的商品，写入 `results/cluster_review_v0.txt`，供人工阅读。

聚类本身**不直接当作类别**：我们发现文本聚类会把“同一设计系列”的商品聚在一起（例如所有 SPACEBOY 商品、所有 I LOVE LONDON 商品），而不是按商品类型分。它的作用是帮助我们看清数据里有哪些商品类型，以及作为第 5 步的兜底。

### 第 4 步：按关键词规则打子类标签（`rules_v0.py`）

- 读完 120 个聚类的样例后，写了 53 条有序的关键词规则，每条对应一个子类（L2），并归入 10 个大类（L1）。
- **按顺序匹配，第一条命中的规则生效**，所以更具体的规则放在前面。例如“LUNCH BAG”（午餐包）必须排在一般的“BAG”（布袋）前面，“HAND WARMER”（暖手宝）要排在“CARD”前面。
- 大类与子类数量：

| 大类（L1） | 子类数 | 例子 |
|---|---|---|
| home_decor 家居装饰 | 14 | 挂饰、招牌与板子、相框、镜子、钟、门垫、靠垫、挂钩、家具与把手、首饰盒…… |
| kitchen_dining 厨房餐饮 | 10 | 杯子、盘碗、蛋糕架、茶具、午餐盒与餐具、厨房纺织品、储物罐…… |
| stationery_gift_wrap 文具与礼品包装 | 7 | 贺卡、礼品包装与标签、礼盒、本子、笔与画具、贴纸、冰箱贴 |
| fashion_accessories 服饰配件 | 6 | 首饰配件、钱包、雨具、暖手宝、钥匙扣与行李牌、衣物 |
| baking_party 烘焙与派对 | 4 | 蛋糕纸杯、派对餐具、派对用品、彩旗与花环 |
| bags 包袋 | 3 | 午餐包、大号购物袋、小布袋 |
| candles_lighting 蜡烛与灯具 | 3 | 烛台与灯笼、蜡烛与香薰、灯具 |
| personal_care 个人护理与手工 | 3 | 纸巾与创可贴、洗浴用品、缝纫与手工 |
| garden_outdoor 园艺户外 | 2 | 园艺户外、宠物用品 |
| toys_kids 玩具 | 1 | 玩具与游戏 |

- 抽查时发现并修正了两个规则错误：
  - “DESIGN” 结尾的 “SIGN” 被误判为“招牌”，导致 “HAND WARMER OWL DESIGN” 被归到招牌，已改为整词匹配；
  - “VINTAGE SNAP CARDS” 是卡牌游戏，却被归到贺卡，已把玩具规则移到贺卡之前。

### 第 5 步：兜底

- 关键词没有命中的商品，看它所在的文本聚类：如果该聚类中已打标签的早期商品有 ≥ 50% 属于同一子类，就采用这个子类（标签来源记为 `cluster_majority`）。
- 仍然无法判断的，标为 `other`。

## 5. 用 v0 得到的探索结果

### 5.1 复查 C 的商品层规则（`step4_checks.py`）

| 范围 | 合格规则 | 前后件同一子类 | 剩下的跨类规则 |
|---|---|---|---|
| 全局 G | 1,116 | 80.7% | 215 |
| C0 | 46 | 93.5% | 3 |
| C1 | 843 | 75.6% | 206 |
| C2 | 1,590 | 75.0% | 398 |
| 随机组 R（60 个组的中位数） | — | 74% | 332 |

和此前的关键词检查一致（`explore_item_rules.py`：宽口径去掉同系列后，G 剩 103 条、C0 剩 0 条、C1 剩 95 条、C2 剩 190 条）。**商品层规则的主要内容是同类换款；C0 在商品层几乎没有可用规则。**

### 5.2 品类层挖规则（`step3_concept_mining.py`）

做法：把每个篮子里的商品换成它的子类并去重（other 不参与），然后用**和 C 完全相同的门槛**（support ≥ 1%，联合次数 ≥ 20，前件次数 ≥ 20，confidence ≥ 0.2，lift ≥ 1；前件 1–2 个、后件 1 个）分别对 G、三个真实群和 20 套随机分组挖规则。Discovery 主样本 7,490 个篮子（去掉只含 other 商品的篮子），每篮品类数中位数 8。

**（1）分群差异第一次明显超过随机分组**

| 差异指标（越大表示差异越大） | 真实分群 L | 随机分组 R 中位数 [最小–最大] | R 不低于 L 的次数 | 经验 p |
|---|---|---|---|---|
| 群与群之间的支持度差异（Bray–Curtis，二品类组合） | 0.1077 | 0.0790 [0.0631–0.0958] | 0/20 | 0.048 |
| 各群与群外的支持度差异 | 0.0897 | 0.0673 [0.0536–0.0864] | 0/20 | 0.048 |
| 各群 Top-10 规则组合的不重合度（1 − Jaccard） | 0.4049 | 0.2576 [0.1212–0.4049] | 0/20 | 0.048 |

- 经验 p = (1 + R 不低于 L 的次数) / 21；20 次随机分组时最小只能到 0.048。
- 前两项都明显超过随机最大值；第三项只是和随机最大值几乎持平地领先，优势较弱。
- 对比 C 在商品层的结果（二商品组间差异 0.2409 对随机最大 0.2403；三商品只超过 5/20 次），**品类层的分群信号清楚得多。**

**（2）各群的特色品类组合（群内比群外更常见）**

| 群 | RFM 画像 | 代表组合 | 群内 / 群外 support |
|---|---|---|---|
| C0 | 较久未购买、低频低金额 | 玩具 → 笔与画具 | 22.8% / 14.8% |
| C0 | | 园艺户外 → 玩具 | 13.9% / 8.4% |
| C1 | 较近期购买、仍以低频为主 | 挂饰 → 烛台 / 礼品包装 | 差距较小（约 2 个百分点） |
| C2 | 更近期、更高频、金额更高 | 招牌 → 门垫 | 10.4% / 6.4% |
| C2 | | 大号购物袋 → 午餐包 | 10.6% / 7.1% |

通俗地说：C0 更偏儿童礼品和文具，C2 更偏家居和厨房的成套采购，C1 介于两者之间。完整表格见 `results/concept_group_representative_rules.csv`。

**（3）全局最有意思的跨品类组合（按 lift 排序，联合次数 ≥ 50）**

| 组合 | 联合次数 | lift |
|---|---|---|
| 钥匙扣 → 钱包 | 137 | 3.5 |
| 暖手宝 → 暖水袋 | 416 | 3.5 |
| 钟 → 暖手宝 | 123 | 2.9 |
| 纸巾与创可贴 → 贴纸 | 219 | 2.7 |
| 蛋糕纸杯 → 派对餐具 | 766 | 2.6 |
| 笔与画具 → 贴纸 | 395 | 2.5 |

这些比“粉色午餐包 → 红色午餐包”更有业务含义。完整列表见 `results/concept_G_top_pairs_by_lift.csv`。

**（4）品类层门槛过松的问题**

沿用 C 的门槛，品类层过线规则多达 3.6 万条（大多是三品类规则），按联合次数排在最前面的都是“烛台 ↔ 挂饰”“玩具 ↔ 挂饰”这类大众组合，lift 只有 1.3–1.6。**品类层需要更高的 lift 门槛或改用 lift 排序**，这要在 Validation 期选择，不能沿用商品层的门槛。

### 5.3 Validation 期的探索性检查（不是正式评价）

每个方法 50 条规则（C 的比例分配：C0/C1/C2 各 5/15/30 条，按联合次数排序）。“命中”指未来篮子里规则的前件和后件都出现。

| 指标 | 全局 G | 真实分群 L | 随机分组 R 中位数 |
|---|---|---|---|
| 命中订单比例 | 63.2% | 50.4% | 42.0%（L 高于 20/20 次随机） |
| 规则在 Validation 期的 lift 中位数 | 1.42 | 1.42 | 1.41 |

- 分群规则稳定地好于随机分组，但**仍然不如全局规则**。
- 品类层命中率天然比商品层高，**不能和商品层命中率直接比较**；跨层比较只能用 lift 或相对热门基线的提升。
- Validation 期按设计用于选择配置；这里只是探索，正式结论要等配置冻结后在 Test 期只评价一次。

## 6. 为什么把 v0 作为基线

1. **透明、可解释**：每个标签都能追溯到一条关键词规则或一个聚类，答辩时可以逐条解释。
2. **完全确定、可复现**：不依赖 GPU 和外部服务；同样的输入重跑得到完全相同的结果（已用两次运行的文件哈希核对）。
3. **覆盖已经足够高**：按购买记录加权，93% 由规则直接命中，other 只有 3.4%；热门商品基本正确。
4. **已经能回答关键问题**：它证明了“品类层能看到商品层看不到的分群差异”，说明这个方向值得投入。
5. **为 LLM 方案提供对照和素材**：
   - **对照**：LLM 标注必须在人工金标准上**超过** v0 才能被采用，否则没有理由增加复杂度；
   - **参考例子库**：v0 中由规则直接命中、且多种写法一致的商品，可以作为 LLM 少样本提示的参考例子；
   - **分歧清单**：v0 与 LLM 不一致的商品，就是最值得人工复核的商品。
6. **退路**：如果 HPC 环境或 LLM 质量出现问题，v0 加人工复核热门商品仍然可以支撑主实验。

---

## 7. 局限（必须如实说明）

1. **没有人工金标准**：v0 的准确率未知，只有一致性指标。
2. **规则由 AI 辅助起草**：关键词规则和类别命名由 Claude 根据聚类样例起草，B 审阅；尚未经其他组员复核（见 `docs/aigc_usage.md`）。
3. **部分子类过粗**：挂饰、玩具、招牌等子类过大，影响品类层规则的信息量。
4. **品类层门槛未调整**：沿用商品层门槛导致规则过多、热门组合占优。
5. **随机对照只匹配了人数**：没有匹配各组的活跃度（订单数、篮子大小），品类层差异有可能部分来自活跃度差异，需要“活跃度匹配”的随机对照来排除。
6. **只有 20 个随机种子**：经验 p 最小为 0.048，结论力度有限。
7. **单一嵌入模型和单一 K**：聚类只用于提出候选和兜底，但兜底的 3.4% 购买仍受 K = 120 的选择影响。

## 8. 复现方法

环境：Python 3.11（测试版本 3.11.15），`numpy 2.4.4`、`pandas 3.0.2`、`scikit-learn 1.8.0`、`torch 2.12.1+cpu`、`transformers 5.13.1`（见 `requirements-taxonomy.txt`）。第一次运行会从 Hugging Face 下载约 90 MB 的 MiniLM 模型；之后可设 `HF_HUB_OFFLINE=1` 离线运行。

从仓库根目录执行：

```bash
python scripts/run_taxonomy.py run_v0
```

依次运行：

| 脚本 | 作用 | 大致耗时（CPU） |
