# 1123 三种分群的共享规则实验

仅更换分群输入特征，比较纯 RFM、RFM＋采购形态、纯采购形态产生的共享规则。G 在三种方案中相同。L 与 A1 直接共享给全店。

## Profile 与 Discovery

- 三种分群使用相同的 2,684 名 Profile 顾客和同一个 K-means 设置。K=3，随机种子 42，10 次初始化。标准化只在 Profile 拟合，R 用原始天数，其余右偏量按约定取 log1p。群号按各群原 RFM 综合分从低到高重编号，重编号只用于一致的群号和平局处理。纯采购形态的 K-means 拟合输入仅包含六项采购形态。
- RFM 为距最近购买的时间、有效购买次数和毛购买金额。采购形态沿用 1122 的顾客级特征，先算每单总件数、不同 SKU 数、最大 SKU 件数占比、单价中位数、低价和高价商品件数占比，再在顾客内取各项中位数。低高单价界线用 Profile 有效商品行的 33% 和 67% 分位数。总件数、SKU 数和单价中位数取 log1p。形态不包含品类 ID 或未来订单。
- 每种真实分群生成 100 套 A1。按 Profile 订单数 1、2、3–4、5–9、10+ 分层，层内用相同种子 1000–1099 打乱真实标签，严格保留每层每群人数。纯 RFM 标签和 A1 逐项对照原 D 输入。
- Discovery 用相同的 7,521 张 Profile 顾客订单和冻结 taxonomy_v1。对 G、每套 L 和每个 A1 使用相同 P1–P5 候选门槛、联合次数／置信度／Lift／规则 ID 排序。按原 D 密集预算算法逐条贡献，跨群无向组合去重，每组合保留入库时的一个方向。共同预算每 10 个组合一档，扫描上限 300，若某配置共同可用预算更小则该配置扫到最大的共同 10 的倍数。对所有系统使用一个 Discovery 热门榜和同范围推荐分数。

## Validation、冻结与 Test

- Validation 为 2010-12-01 至 2011-06-01，Test 为 2011-06-01 至 2011-12-01，左闭右开。全店原始覆盖包含匿名订单，按完整共购集合匹配，一单最多计一次。原版 quality_v1 和严格版质量仅在有顾客 ID 的订单上验收并计算可靠覆盖。沿用 D 的证据量、Lift、Added Value 5／10 pp 和三品类增量门槛。每套系统在 Validation 固定跨配置和预算的 BY 家族。Test 在各自冻结名单上做 BY 校正。
- 三种分群在共同的 P 和预算下比较。主选择用原版可靠覆盖，权重为 **50% G＋50% 三套 L 的平均值**，每 10 组合扣 0.50 个百分点。取评分最高的 P 和预算，平局取较小预算再按 P 编号。另报每个分群各自按 G/L 等权会选出的 P 和预算。A1 与推荐指标用于评价。
- 冻结统一配置和预算、304 套规则库（1 个 G、3 个 L、300 个 A1）、各名单和 Discovery 分数、热门榜、协议、代码与输入哈希。冻结完成后才读取 Test 时段用于评价。该历史 Test 曾在 D 分支公开，1123 是补充评价。
- Validation 输出完整覆盖和质量网格，并在选定配置上用固定推荐方式复核 Hit@5。Test 对固定名单报告覆盖、质量和推荐。推荐遮挡每单一个 L2，用原 D 可复算方式选择遮挡，各系统使用同一可见购物篮。按共享 Discovery 置信度、联合次数、Lift、规则 ID 排序，去重后件并去掉已见品类，从同一张热门榜补到最多五项。比较纯热门、G＋热门、三套 L＋热门与各自 A1。报告配对新命中、丢失命中和净差，以及按顾客配对重抽的 95% 区间。匿名订单按单形成独立抽样层。

## 运行

本目录的 `run.py` 复用相邻 `repository` 的 D 运行器、A 冻结快照与 C 交接，并复用 `1122/retail_data.py` 的单篮采购形态定义。默认结果写入 `results/`，复算可用 `--out` 另开路径。

```powershell
python -X utf8 -B run.py discovery
python -X utf8 -B run.py validation
python -X utf8 -B run.py freeze
python -X utf8 -B run.py test
python -X utf8 -B report.py
```
