# D 组重做协议 · 去重共享与全店评价

主问题是：用同一批历史订单构建等容量的共享规则库时，真实分群挖掘 L 能否在未来订单上比全局 G 和活跃度匹配随机分组 A1 提供更好的共购覆盖、规则质量或推荐命中？

本轮沿用已报告过的历史 Test 时段，定位为 Test 补测。此文件先于本轮 Validation 运算写定。以下数值决策是本轮工作约定。

## 1. Discovery 组库

- 保留 Profile 冻结顾客标签。用原 Discovery 期 7,521 张 Profile 顾客订单、冻结 taxonomy_v1 的 L2 品类，订单内按品类去重，排除 `other`。
- G 使用全部 7,521 单。L 按真实标签分三群。每套 A1 按各自历史频次匹配标签分三群，使用种子 1000–1099。
- 沿用 C 的 P1–P5 阈值。每个挖掘范围内依次按联合订单数、置信度、Lift 降序和 rule_id 升序。只使用 Discovery 证据。
- 预算单位为不同无向品类组合。逐位合并时，在还有没入库候选的群中，选「目前已贡献数 − 当前名额 × Discovery 订单占比」最小的群，平局按群号。按该群原排序拿下一个新组合，并保留这个方向。每个组合只录入一次。G 按同样组合键从全局排序录入。
- 每个 P 的可比较上限取 G、L 和全部 A1 都能凑足的最大 10 的倍数，并把本轮扫描封顶在 300 个组合。先扫描原上限的三倍，以覆盖更多边际区间，再明确标注结果依赖已扫描范围。以 10 为步长，80 是 90 的前缀。超过 100 的候选使用相同的 Discovery 门槛。
- 对全部入库方向，用同一批 7,521 张 Discovery 订单记录全局打分。热门榜按 L2 在该批订单中的出现次数降序，平局按品类 ID 升序。

## 2. Validation 选择配置和容量

- 期间为 2010-12-01 至 2011-06-01，左闭右开。完整共购覆盖分母为全店有效订单，保留空篮与单品类篮，匿名订单也参与。命中任一规则的完整组合计一单。
- 原版 quality_v1 在当期有顾客 ID 的订单上验收。前件至少 20 单和 10 人，联合至少 10 单和 5 人，单一顾客的联合贡献最多 50%。Lift 至少 1.2，Added Value 至少 5 个百分点，BY 校正后的 q 至多 0.05。三品类置信度相对两个单品类前件分别至少提高 5 个百分点。严格版只把 Added Value 提到 10 个百分点，作为敏感性结果。
- 每套系统对覆盖整个 Validation 网格的入选方向并集做一次 BY 校正，用固定验收结果计算各档增量。质量通过率分母为规则数，可靠覆盖分母为有顾客 ID 的有效订单数。另报合格规则在全店订单上的覆盖。
- 每档报告 G、L、100 套 A1。每加 10 个组合，报告原始全店覆盖新增单数、原版和严格版可靠覆盖新增单数、该档新规则合格数。A1 用于描述分群对照。
- 主选择规则兼顾边际增益和整体表现。对 G 和 L 分别算各自在完整网格上的最高全店原始覆盖、最高原版可靠覆盖，共四个参照值。合格档要求四项各距自身参照至多 **1 个百分点**。优先在合格档找后续两段各加 10 个时，G 和 L 的原始覆盖与可靠覆盖增量均低于 **0.50 个百分点**的档位，取其中最小预算。0.50 pp 约等于全店 Validation 的 40 单或有 ID 样本的 37 单。
- 如果没有合格档被后续两段同时验证为低增量，选择最小的合格档，并明确记录未确认平台。若四项要求没有共同解，取四项中最大短缺最小的档位。选择按预算、最大短缺、平均原始覆盖、平均可靠覆盖和 P 编号稳定打破平局，最后一种情形先比较最大短缺。另报 0.5／1.0／2.0 pp 容许差距与严格质量敏感性。Validation 选择不使用 Test 或 A1 的相对排名。

## 3. 冻结

- 只冻结 Validation 主选择的一组 P 和 B，对应 G、L 和 100 套 A1 的具体组合、保留方向、组库顺序与 Discovery 推荐分数。
- 保存 Validation 选择表、规则名单、热门榜、运行协议、运行代码、关键输入及原 A 快照的 SHA-256。冻结步骤完成后，Test 运行器先校验哈希，再提取历史 Test。

## 4. Test 评价

- 期间为 2011-06-01 至 2011-12-01，左闭右开。三套共享规则直接适用全店，不按群限制。完整共购覆盖报告全店、历史顾客、有 ID 的非历史顾客及匿名订单。
- 原版与严格版质量验收沿用 Validation 定义，在当期有 ID 的订单上重新计算。此处每系统 BY 家族为冻结的 B 条方向。Validation 的预算网格使用更大的固定家族，直接跨期比较通过率时注明范围差异。合格状态只用于可靠覆盖指标，完整名单用来评价原始覆盖和推荐。
- 推荐任务只用至少有两个有效 L2 品类的订单。用稳定订单 ID 的 SHA-256 选择一个品类遮住，所有系统使用同一个遮挡。只用可见品类触发规则。按共享 Discovery 置信度、联合次数和 Lift 降序，rule_id 升序。移除已见品类和重复后件，每个后件采用其最高排序的触发规则，剩余位置用共同热门榜补足五项。
- 对照纯全局热门、G＋热门、L＋热门及 100 套 A1＋热门。报告 Hit@5 与 NDCG@5，及相对纯热门、相对 G 的新命中、丢失与净差。规则库始终每个组合保留一个方向。
- 报告 G/L 差和 A1 中位、范围、达到或超过 L 的次数。对全店覆盖、质量可靠覆盖和推荐 Hit@5 做 2,000 次配对重抽。已识别订单按顾客抽样，匿名订单以单笔订单为单位构成独立抽样层。覆盖与推荐分别使用自己的固定分母。

## 复算

准备原 D 的 C 交接与本地订单文件，使用原 D 环境。仓库中的运行器位于本实验目录。四步分别运行，复算可用新的输出目录。

```powershell
python -X utf8 -B experiments/shared_full_store/run.py discovery
python -X utf8 -B experiments/shared_full_store/run.py validation
python -X utf8 -B experiments/shared_full_store/run.py freeze
python -X utf8 -B experiments/shared_full_store/run.py test
```

输出目录含 Discovery 核验与规则路径、Validation 网格、冻结清单、Test 聚合表和结果报告。
