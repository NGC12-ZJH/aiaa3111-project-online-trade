# Validation 热门补齐与局部残差重排

在冻结后的 Validation 扩展探索中，使用同一批 4,862 单与原 Discovery 参数。Top‑5 使用同一批 4,311 张可遮挡订单、同一个遮挡品类。分别报告 P1–P5 的 20、50、100 档与 100 套 A1 活跃度匹配随机分组。

## 一、规则优先，热门补到五项

- G 用原全局规则和 Discovery 全站热门榜。L 用各真实群原规则和各群自己的 Discovery 热门榜。A1 按各随机群的 Discovery 数据独立做同样的事。
- 先推荐规则触发的后件，再按热门榜补新后件。过滤已经看见的品类，每个后件最多出现一次。规则按 Discovery confidence、联合次数、lift、rule_id 排，热门按出现订单数排。
- 限群使用各群自己的规则。C0、C1、C2 表是同一批真实群订单上的各方案对照。计算 A1 时先按每个种子的随机群服务订单，再按订单的真实群切分。
- 每个方案在每张可评订单上都给出五项。同一分群的热门榜单独做基线，便于判断规则加入后有没有改变命中表现。

## 二、剔除 G 已占规则，局部规则重排后测残差

1. 每个 P/B 固定原 G Top-B。各真实群与随机群都从自己满足原 P 门槛的完整 Discovery 候选里剔除 G 的相同有方向 rule_id，再按自己的 Discovery Added Value 或群内外 confidence 差排序。
2. Added Value 为群内 confidence 减去群内后件基础出现率。群内外差要求 Discovery 群外前件至少出现 20 单，群内沿用原门槛。分数相同时依次比较联合次数、confidence、lift 和 rule_id。各群沿用按 Discovery 订单量计算的原配额。候选不足会记录，实际未补满的结果行有 0 行。
3. 同一 P/B 的真实分群和所有 A1 方案共用两种 G 残差。**完整共现残差**是原 G 规则没完整覆盖的订单。**推荐残差**是 G＋全站热门仍没猜中遮挡品类的订单。局部残差推荐仅用重排规则，按分数尝试最多五个不同后件。
4. 限群只用自己所属群的候选。共享允许所有订单匹配所有群贡献的候选，允许跨群重复方向规则占名额，订单命中与候选后件仍去重。不同方向规则数在明细中给出。
