# Online Retail II 四时期数据处理方案

## 1. 目标

使用 UCI Online Retail II 两年交易数据建立独立的四时期数据处理流程，同时保持现有
一年数据交接接口：`clean_transactions`、`orders`、`baskets` 和 `baskets_long`。

## 2. 规范来源与跨表重叠

工作簿包含 `Year 2009-2010` 和 `Year 2010-2011` 两张表，两张表在
2010-12-01 至 2010-12-09 重叠。规范来源固定为：

```text
InvoiceDate < 2010-12-01  → Year 2009-2010
InvoiceDate >= 2010-12-01 → Year 2010-2011
```

被排除的重叠行仍保留在干净明细中用于追溯，但不进入金额、购物篮、RFM、规则挖掘
或评价。需要分别审计跨表完全相同记录、重叠订单以及两个版本不完全相同的订单。

## 3. 清洗口径

- 标识符统一保存为字符串；
- 商品编码统一为大写，同时保留原始值；
- 取消订单、负数量、负价格、零数量和非商品编码不进入主购物篮；
- 零价格保留审计，但不进入主购物篮和 RFM Frequency；
- 规范来源内部的完全重复候选只保留第一条进入主金额和购物篮；
- 缺失客户保持空值，不填充为同一个匿名客户；
- 极端数量和金额不自动删除，先进入人工审计和敏感性分析；
- 单商品购物篮保留；
- 同一商品在同一购物篮中只出现一次。

## 4. 四时期职责

### Profile

使用 `[2009-12-01, 2010-06-01)` 的有效正向订单计算 RFM，以 2010-06-01 为
Recency 截止点。只在 profile 内选择 K、拟合聚类并生成客户级随机分组，随后冻结标签。

### Discovery

使用 `[2010-06-01, 2010-12-01)` 中属于冻结 profile 客户的有效购物篮。G、L、R
使用同一批客户订单、相同候选定义和相同系统总规则预算。

### Validation

使用 `[2010-12-01, 2011-06-01)` 选择 discovery 已产生的支持度、置信度、冗余
过滤和规则预算配置。不得重新聚类或改变清洗口径。

### Test

使用 `[2011-06-01, 2011-12-01)` 做一次最终评价。不得重新聚类、重新挖规则、调参、
删除规则或修改数据处理设置。

## 5. 输出

主输出保持原接口：

```text
clean_transactions.csv.gz
orders.csv.gz
baskets.csv.gz
baskets_long.csv.gz
```

新增审计输出：

```text
sheet_reconciliation_summary.csv
cross_sheet_overlap_exclusions.csv
cross_sheet_invoice_conflicts.csv
four_period_retention_summary.csv
period_eligibility_summary.csv
```

同时继续生成排除原因、订单冲突、特殊编码、零价格、重复候选、极端记录和运行清单。

## 6. 验收条件

1. 两张工作表原始行数与 UCI 总行数对账；
2. 规范保留行加跨表排除行等于物理原始行；
3. 跨表排除行不进入主金额和购物篮；
4. 一张订单只属于一个时间阶段；
5. 订单金额满足 `gross - return = net`；
6. `baskets_long` 与 `baskets.items` 完全一致；
7. G/L/R 合格订单属于同一个冻结 profile 客户总体；
8. 无未来订单客户不创建空购物篮；
9. Test 不参与聚类、规则发现或参数选择；
10. 重复运行得到一致的核心数量和文件哈希；
11. Manifest 记录输入哈希、配置、代码版本、输出和核心数量；
12. 在交给 B、C、D 前由另一成员复核。
